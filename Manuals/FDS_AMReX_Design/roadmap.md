# FDS-AMR roadmap

Owner: Spec & Program Lead · Status: draft v0.4.21 (2026-09-26; changelog in README.md) · Source pin: FireX 36975d765f on branch `FDS-AMReX` (this repository; renamed from `AMReX`, D-037)

No calendar dates are set. Durations are **estimates** in elapsed working weeks for the current team on the current box. Confidence is low until Phase 1 closes; they are re-estimated at every milestone. Requirement IDs refer to requirements.md; risk IDs to risks.md.

## Principles

1. Every phase ends with a measurable gate tied to requirement IDs. Any gate that uses a proposed number needs the project owner's approval of that number first.
2. Keep FDS runnable at every step. With `USE_AMREX=OFF` the build must equal baseline (IR-006).
3. Add numerics before subsystems: uniform first, then multi-level transport, then pressure, then walls, then everything else.
4. Machine limit: 8 cores, 16 GB, no GPU. Any test that does not fit is deferred and logged, not dropped silently. GPU execution of the full step is required (D-027, NFR-043), but on the development machine GPU work is compile-only plus host fallback (R-38). FireX's HYPRE GPU offload must stay compilable and is checked on CPU only (FR-038, R-40).
5. Code base: FireX `36975d765f`, branch `FDS-AMReX` (D-005, D-037; `marcosvanella/fds:FDS-AMReX`), in the project owner's fork (Q3, decided for now; going upstream is decided later, and NIST conventions are kept where cheap, charter §7). The branch is read-only through Phases 0-1. No code lands on it before M1 (amended by D-044: during the spec phase the only commits allowed are Chief-Architect-approved documentation snapshots under `Manuals/FDS_AMReX_Design/`, generated by `tools/sync_design_docs.sh`); after the spec phase the AMR Chief Architect approves and makes the first commit (D-034; commits authored under a dedicated project identity, pushes only with the project owner's approval, D-037). From then on FireX is merged into `FDS-AMReX` daily, each merge gets a quick Tier-1 smoke run, and V&V baselines and source line citations are re-pinned at each milestone (D-034; adopted plan pending V&V Lead confirmation, A-42; R-44). Spikes before then build from copies outside the worktree.
6. Environment check at every milestone entry. Run the scripted toolchain check (A-21): GNU 14.2 + OpenMPI 5.0.7, oneAPI, HYPRE (FireX-fetched `63331f19c7` = v2.32.0-24 and the development machine's 3.0.0, versions from build provenance), FFTW headers. Record the versions next to the baselines. A missing toolchain blocks only the gates that need it, and is logged (R-32).

### Phase 2: Single-level AMReX-backed prototype (uniform-grid equivalence)
- **Objective:** run FDS with field storage and the level-0 box layout owned by AMReX, zero refinement levels, and reproduce baseline.
- **Entry:** M1; first commit on branch `FDS-AMReX` approved and made by the AMR Chief Architect (D-005, D-034, D-037); daily FireX merges start with development (D-034, R-44).
- **Deliverables:** `USE_AMREX` CMake option; level-0 driver; ghost fill replacing the same-resolution parts of `MESH_EXCHANGE`; `amrex::FFT::Poisson` as the uniform level-0 solver behind the composite-solver interface (FR-037, D-021; `pois.f90` not ported) with per-step solver selection (FR-039); single-level composite MLMG for multi-box inputs (from P2); comparison script (NFR-040); P3 completion.
- **Demo gate M2a** (D-006; in/out list in spec-responses.md (a)): full FDS steps through the shim on `shunn3_32`, `csmag_32` (FR-001) and `shunn3_4mesh_32` (FR-002). All three: bitwise checks of the explicit kernels (mass, velocity predictor, divergence) on frozen input against single-mesh FDS (for `shunn3_4mesh_32`, its derived single-mesh copy, A-24); full steps within tolerance (T2) against single-mesh FDS and, for `shunn3_4mesh_32`, against 4-mesh FDS; one-solve `H` vs GLMAT within eps_H (D-022). Periodic only; no walls, combustion, radiation or particles; gfortran only; 1 and 4 ranks; `OMP_NUM_THREADS=1`; IR-006 on the same cases; NFR-030 and f_pres measured (A-22). - **Exit criteria (M2):** FR-001 on single-mesh anchors (shunn3_32 first, then `ns2d_16` and the wall/radiation/particle anchors); FR-002 on multi-mesh anchors (kernel-level bit-parity against single-mesh inputs, whole runs T2; D-022); FR-005 (with P2's `H` differences for (iii)); FR-038 (FireX HYPRE options, CPU only); FR-061; FR-062 S-B coupling (charter Q12 decided, D-039) with its tolerance class across box splits set (owner AMR Radiation Lead; FR-061 depends on it); IR-001; IR-006; NFR-010/011/012; NFR-020 (oneAPI restored, A-18 closed); NFR-022; NFR-030/031 measured (not yet required).

### Phase 4: Composite pressure solve
- **Objective:** replace per-mesh FFT plus interface iteration with a composite solve across levels at both pressure solves per step. Following the ADR-002 leaning: one global dt, no subcycling, MLMG (or HYPRE) composite solve.
- **Entry:** M3; ADR-002 accepted.
- **Deliverables:** composite Poisson operator and BCs; replacement for `PRESSURE_ITERATION_SCHEME` in AMR mode; composite divergence check; single-zone background pressure on composite volume.
- **Exit criteria:** FR-014, FR-022 (gas), FR-023, FR-030..034 (FR-034 multi-zone with leakage included, per the FR-034 ruling, final), FR-036. Conservation check: if FR-014/022/023 fail or pass only marginally, the cause is fixed within Phase 4. No sync projection is needed under a global dt, so this is not an R-05 trigger; R-05's gate is now the Phase 6 subcycling decision (Pressure Lead, 2026-09-25). **R-26 shim-exit review** if ADR-001 adopts the shim: a kernel-extraction date is set, and the regrid rebuild measured in P3/Phase 3 is ≤ 10% of step time.
- **Owners:** AMR Pressure Solver Lead (lead), V&V Lead.
- **Dependencies:** ADR-002, ADR-003 (solid treatment in the operator).
- **Estimate:** 4–8 weeks.

- **Entry:** M4.

- **Dependencies:** ADR-003.
- **Estimate:** 4–8 weeks.

### Phase 6: Synchronization corrections and (conditional) subcycling
- **Objective:** coarse-fine synchronization corrections (divergence/flux consistency beyond Phase 3-4, background-pressure dP0/dt correction for multi-zone) and, **depending on ADR-002 S1**, time subcycling (D-007, proposed; final scope needs the project owner):
  - S1 work ratio ≤ 1.5×: **sync corrections only**; subcycling moves to "Out of roadmap".
  - 1.5× < ratio ≤ 3×: 6a sync corrections; 6b subcycling optional, with go/no-go at M5 on the re-measured NFR-032 projection. ADR-002 Option C data model kept from Phase 3.
  - Ratio > 3×: subcycling pulled forward. Option C data model mandatory from Phase 3; Phase 6 starts at M4, in parallel with Phase 5, and is a precondition for NFR-032.
- **Entry:** M5 (ratio ≤ 3×) or M4 (ratio > 3×). R-05 applies only once subcycling is scheduled.
- **Deliverables:** sync-projection design ADR (ADR-002 follow-on); subcycled advance; dP0/dt correction for multi-zone background pressure.
- **Exit criteria:** FR-034 (dP0/dt sync); new sync/subcycling requirements added to requirements.md at Phase 6 entry; if subcycling is scheduled, FR-014/020..023 still pass with subcycling on and the measured speed-up vs global dt is reported (target TBD(Pressure Lead)).
- **Owners:** AMR Pressure Solver Lead (lead), Chief Architect, AMR Solid Phase Lead (per-level wall cadence under subcycling, FR-047; FR-041b if scheduled), V&V Lead.
- **Dependencies:** Phase 4; ADR-002 S1 result (A-19). Scope per D-007.
- **Estimate:** 4–8 weeks.
