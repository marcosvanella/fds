# Patches for the project owner: states and validation

Owner: Spec & Program Lead · Status: v0.4.41 (2026-10-04) · One table for the project owner. Patch sources and index: `upstream-patches/README.md` (the Legacy Mapper keeps the index). Run evidence: `(local V&V run directory)/upstream-patch-validation/` (`RESULT.md`, `PROGRESS.md`, `logs/`, `intel/UP-0008.md`, `intel/UP-0011.md`); `RESULT.md` is partial and still being written by the GNU Build Chief and the Intel Build Chief, so a blank means "no result recorded yet", not "failed".

Numbering (README Process rules, A-63): `UP-NNNN` patches change upstream FDS source and are for the project owner to review and commit upstream; nobody else commits or pushes them. Bare `NNNN` patches are driver-series patches for the AMR branch only. `UP-0006` and `UP-0007` are driver-side proposals for Role 1 (kept under their names), not upstream changes; `0010` is a driver-series patch.

State words: **proposed** means written and checked by its author, not yet reviewed by the project owner; **reviewed** means the project owner has read it; **committed upstream** means the project owner has committed it. Nothing is reviewed or committed upstream yet.

Standard behavior-unchanged check (README rule 4 for patches): `tools/patch_check.sh` builds the unpatched and the patched source and compares the output files of the standard cases bitwise; a declared change is listed with the patch. Toolchains: GNU 14.2.0 with Open MPI 5.0.7 (master `ce1f659cd4`, Release `-O3` and Debug `-O0 -fcheck=all`); Intel ifx and icx 2026.1.1 with Intel MPI 2021.18.1 (FireX `36975d765f` and master `ce1f659cd4`, Release and checked builds).
