# Draft: generating the K2 GPU kernels from upstream FDS loops

Status: draft for discussion. It records what the prototype in `amrex/s4_mass/s5_gen/` does after round 2, the WALL flat tables it relies on, and what is open. Coverage numbers: `docs/inventory/gpu_generator_coverage.md`. Source reference: FireX `36975d7`. Target: K2 only (Fortran with OpenMP target, the `s4_omp.inc` convention). K1 (an AMReX `ParallelFor` backend) is not pursued. Cut-cell, cut-face and CFACE loops are out of scope (deferred: geometry refactor).

## Goal
Keep the GPU kernels in step with upstream by reading the upstream loop text and emitting the kernel, instead of porting each loop by hand. 25 kernels exist: the seven `DIVERGENCE_PART_1` loops of round 1 plus 18 in `mass.f90`, `divg.f90` and `velo.f90`, 6 of them wall loops. Each is bit-equal to the verbatim upstream loop text (coverage doc, section 6).

## Parser
fparser2 (0.2.5, Fortran 2003 mode); 33 of the 34 `Source/*.f90` files parse after one in-memory change (`IMPLICIT NONE (TYPE,EXTERNAL)` to `IMPLICIT NONE`). The exception, `pois.f90:7103`, is host-only. Comments are dropped by the parser, so inline markers use a separate text scan; the older regex lexer in `tools/inventory/` stays in use for the bulk survey.

## Markers
Inline form, in upstream source, ignored by every compiler as a comment:

    !$GPU KERNEL <name> [HOST] [UNIQUE] [PRIVATE(a,b)] [REDUCTION(op:v)] [COLLAPSE(n)] [LAYOUT(exact)] [ARGS(a,b,...)]
       ... whole-array assignments and/or one K,J,I (or wall) loop nest ...
    !$GPU END KERNEL <name>

`HOST` excludes the loop and lists it in the report. `UNIQUE` asserts that distinct walls write distinct cells (needed for a wall write when upstream has no `!$OMP DO`). `IDEMPOTENT` permits several walls to reach one element only when every store writes identical bits; the generator checks the text (the stored value, followed through scalars, reads no per-wall datum except `BC%II/JJ/KK/IIG/JJG/KKG/IOR`, no `IW`, no flat table and no `IW`-indexed mesh array; the loop does not read an array it writes through wall subscripts). `LAYOUT(exact)` takes dummy bounds from the `ALLOCATE` text. Enable it with `--inline FILE` or `policy.inline_files`; the parser is the existing one (`inline_markers()` in `s5gen.py`). Syntax errors exit 2 with the offending tag. A name may be inline or in the sidecar, not both.
**Fall-back:** the sidecar `s5_markers.toml` carries the same information (routine, line range, anchor text, pinned `args`) for upstream that must stay unmodified. An inline and a sidecar entry for one kernel produce identical kernel text (checked).

## Intermediate representation and analysis
Per kernel: name; routine and lines; loop nest (or wall loop); for each array its rank, bounds, stencil reach and use; scalars as by-value, private or reduction; callees; alias provenance; directive and reason. The plain-data IR is printed in `generated/s5gen_report.md`; the argument manifest is `generated/s5gen_args.json` (name, role, dims, intent per argument: the contract with the C++ shim).
The generator resolves pointer aliases through `POINT_TO_MESH` (hygiene item 8, `Avoid pointer re-aiming (UU => US) inside a routine`): `X => M%Y` and aliases set in the routine preamble become flat dummies; a pointer set outside the routine is diagnosed and refused. For hygiene item 1 (`Hot loops in own routines with flat arrays as arguments with INTENT and explicit bounds`), `layout = "exact"` reads the bounds from the `ALLOCATE(M%X(...))` text in `init.f90`/`read.f90`: `-1:IBP1+1` cell arrays, `-1:IBP1` face arrays, 4-D species arrays with lower bound `NL` (0 or 1, init.f90:605-609), `0:IBAR` grid vectors. `exact_check()` verifies the stencil reach against these bounds. Other rules: intents derived from use; private scalars found by dataflow; fixed-extent private copies of allocatable locals; `SUM`, `MAXLOC`, `DOT_PRODUCT` expanded in source order and left-to-right parentheses (bitwise rule); refusals (exit 2) for loop-carried scalars, writes not at the loop variables, possible aliasing and a wall write without an ordering argument.

**Static or time-varying; who syncs.**
- *Static between geometry changes (setup-time gather):* `BC_II/JJ/KK/IIG/JJG/KKG/IOR` (init.f90:3330-3339, 3437-3443), `W_THIN` (init.f90:3315), `EW_NIC` (main.f90:2111), `MW_SPEC`. Re-gather after `REASSIGN_WALL_CELLS` (init.f90:4898; called from main.f90:1793 when an obstruction is created or removed) and when `WALL` grows (func.f90:4003-4014 reallocates in steps of 1000, so the table extent changes).
- *Changes at geometry events and in a few places:* `W_BOUNDARY_TYPE` (init.f90:5076-5107, 5192; main.f90:2772). Same re-gather.
- *Time-varying, one writer per step:* `EW_BOUNDARY_TYPE_PREVIOUS` (written velo.f90:2667 each `MATCH_VELOCITY`), `B1_RHO_D_DZDN_F` (written by the translated loop divg.f90:223-228 and by wall.f90:946, 952), `UVW_SAVE`/`U_GHOST`/`V_GHOST`/`W_GHOST` (written velo.f90:2732-2832 and ccib.f90, deferred), `UN_WALLS`.
- *Owner of the sync:* the driver shim (AMReX side). Per step, before a kernel that reads a time-varying table, the shim scatters host-written fields in (e.g. `B1_RHO_D_DZDN_F` after `WALL_BC`); after a kernel that writes one (`B1_RHO_D_DZDN_F` store at divg.f90:223-228) the shim keeps it on the device or scatters it back if host code reads it. The generator emits only the kernel and the argument manifest; it never copies.
**Ownership.** The AMReX side allocates and owns every flat table (device memory, sized by the box's wall count) and passes them as explicit-shape arguments; Fortran kernels never allocate and never see a derived type. `NWE`, `NWI`, `NS`, `NL` are arguments. The upstream derived-type arrays stay valid on the host for host-only routines (protocol item 5).
**Interaction with the AMReX box layout.**
- *Per-box wall lists (ruling W1, ADR-001).* One set of wall tables per mesh, in upstream wall order, indexed by the upstream (global) `IW`; plus, per box, two integer index lists: `WLIST_EXT` (external walls of the box) and `WLIST_INT` (internal walls), with the counts `NWL_EXT` and `NWL_INT`. A wall kernel written with the sidecar attribute `wlist = true` (kernel name suffix `_wl`) loops `DO IWI = 1, NWL_EXT` with `IW = WLIST_EXT(IWI)` for a loop over external walls, `NWL_INT` and `WLIST_INT` for an internal-only loop, and for a loop over both one loop over `NWL_EXT + NWL_INT` that takes the external list first (`IF (IWI <= NWL_EXT) THEN IW = WLIST_EXT(IWI) ELSE IW = WLIST_INT(IWI - NWL_EXT)`). The body is unchanged and `IW` becomes a private loop-local scalar. The lists are read-only integer arguments listed with the wall tables in the argument manifest (role `wall`, type `WALL_LIST`). Driver contract (checked by the driver, not by the kernel): each list is strictly ascending, has no duplicates and stays inside its range (`1..NWE` for the external list, `NWE+1..NWE+NWI` for the internal list; for a loop bounded by `N_INTERNAL_WALL_CELLS_AUX`, the internal walls inside that bound). Ascending order keeps the upstream wall order within a box, and a mesh-wide `UNIQUE` or `IDEMPOTENT` argument then holds for every box. For one box per mesh the lists are the identity. The plain kernels (loop `1..NWE[+NWI]`) stay in the generated file next to their `_wl` twins; the `_wl` twin is the form the driver calls. In the sidecar a twin is the two-line entry `name = "<k>_wl"`, `wlist_of = "<k>"`: it copies the plain entry (location, anchor, layout, attributes) and adds `wlist = true`, so the drift anchor lives in one place.
- *Global `IW` only (ruling W1).* The kernels use the mesh-global upstream `IW` everywhere: the wall tables, the `EW_*` tables (extent `NWE`) and the mesh arrays indexed by `IW` (`UVW_SAVE`, `U_GHOST`, ...) are the per-mesh arrays, so there is no local-to-global map and host routines see one numbering. The earlier idea of one table set per box with a local numbering is superseded. Order: external walls first (1..NWE), then internal walls, as upstream (init.f90:48), so `EW_*` and the loops `1..NWE` stay prefixes of the tables.
- *Ghost and external faces.* `BC_II/JJ/KK` are the ghost cell outside the box; the ghost cell of a wall on a box edge may belong to a neighbouring box and then comes from `FillBoundary`. Kernels write the ghost cell (`UP(BC_II,BC_JJ,BC_KK) = ...`), so the box arrays must carry at least one ghost layer, and index bounds follow `layout = "exact"` (`-1:IBP1+1`). Walls on a box face shared with another box of the same mesh are not walls (no `WALL` entry upstream); the driver must not create one.
- *Coarse-fine.* `EW_NIC>1` marks an interface cell that has several neighbour cells (divg.f90:210-218); the translated loop already branches on it. `W_BOUNDARY_TYPE == INTERPOLATED_BOUNDARY` (cons.f90:93) stays the mesh-to-mesh case. The neighbour-mesh arrays (`OMESH(NOM)%...`, `EW_IIO_MIN..`) are not in scope (T4 in the coverage doc); they wait for the exchange-buffer layout.
**Generator mapping.** Policy `[policy.wall]` in `s5_markers.toml` (`types`, `prefix`, `extent`, `arrays`). Rules: (1) an alias statement `WC=>WALL(IW)`, `BC=>BOUNDARY_COORD(WC%BC_INDEX)`, `B1=>BOUNDARY_PROP1(WC%B1_INDEX)`, `EWC=>EXTERNAL_WALL(IW)` is elided; (2) `WC%X`, `BC%X`, `B1%X`, `EWC%X` becomes `<prefix>X(IW)`; a species component indexed `(N)` becomes `<prefix>X(IW,N)`; (3) the table is an argument whose extent is the policy extent; (4) a derived-type reference with no rule, a pointer alias outside the recognised set (`B2`, `SF`, `OM`), or an accumulation into a mesh array through wall subscripts is refused with the reason; (5) a write to a mesh array through `BC_IIG`-style subscripts needs an upstream `!$OMP DO` on the loop or a `UNIQUE` marker, since the subscripts are data, not loop variables; (6) loops over `1:N_EXTERNAL_WALL_CELLS` use the `NWE` extent for `EW_*` and `UVW_SAVE` tables.

## Directive policy
| Region | Directive | Switch |
|---|---|---|
| Contains a `CALL` (callee carries `declare target`) | `target teams distribute parallel do collapse(n)` (default, as in S4d). Never plain `target teams loop` | `s5gen --callee-directive=dpd` (default) or `bind`; in the generated file `-DS5_CALLEE_DPD` / `-DS5_CALLEE_BIND` override the generated default; defining both is a compile error |
| Contains a `CALL`, bind selected | `target teams loop collapse(n) bind(teams,parallel)` on NVHPC only (`S4_LOOP_BIND`, `S4_BIND` in `s4_omp.inc`); every other compiler keeps the DPD form because `S4_BIND` is an empty macro and the macro falls back | `-DS5_CALLEE_BIND` |
| No callee, private array | `target teams distribute parallel do` | `-DS5_FORCE_DPD` forces DPD for all regions |
| No callee otherwise | `target teams loop collapse(n)`; the bind clause is added only with `-DS4_BIND_ALL` (off by default) | |

Reasons. (1) A slow `teams loop` around a callee is expected OpenMP behaviour: the compiler must assume the callee contains a parallel loop, so only the outer loops get teams and one thread per team is active. (2) A private scalar passed `INTENT(OUT)` to a `declare target` callee gives wrong results under `teams loop`; this is a confirmed compiler defect (NVIDIA TPR #39018), not a generator error. Initialising the private scalars before the call was tried and does not fix the real kernels (H_RHO_D_DZD stays wrong, all stay slow, `-Minline` does not help), so it is not used. S5-bind results (`prototypes/s4_cuda_mass/s5_bind/`, device run, seven round-1 nests, n=128 K2 median): plain `teams loop` 5.1 ms H_RHO_D_DZD, 7.6 ms CP_RHG, 11.5 ms CONDUCTIVITY, 11.3 ms DP_SPECIES with wrong H_RHO_D_DZD and DP_SPECIES values; `bind(teams,parallel)` 0.52, 0.50, 0.57, 0.64 ms, and `distribute parallel do` 0.52, 0.51, 0.58, 0.64 ms, both bitwise equal to the CPU in all 14 comparisons. The two cost the same, so DPD is the default and bind the switch. Callee regions today (five, the rest of the 25 kernels have none): `h_rho_d_dzd`, `cp_rhg`, `conductivity`, `dp_species`, `mu_dns`; the wall kernels have no callee and keep `S5_LOOP_WALL` (`distribute parallel do`, 1-D). The directive macro name is part of the golden signature, so a change of policy fails generation until the golden file is updated.

## Build integration
CMake `integration/s5gen.cmake` and make `integration/s5gen.mk` run the generator on the synced `Source/` and write the kernels, header and `s5gen_args.json` into the build tree (variables `S5GEN_INLINE_ARGS` / `S5GEN_INLINE` add `--inline FILE`). The make fragment was exercised, the CMake one was not run. Generated files are committed in the prototype only so that diffs are visible.

## Upstream merge check (ADR-001 "Upstream FireX merge protocol for ported kernels")
**How the generator fits.** A merge that changes only arithmetic inside a marked loop regenerates silently and the bitwise gate runs. A change of operand set, loop order, alias or flat-table field changes the signature in `markers/golden_signatures.json` (read/write signature plus `body_sha` per kernel) and stops the build with a message. Moved code is relocated through the anchor and reported as drift. 23 negative checks (`test/test_generator_checks.py`) cover: new operand, swapped loops, parse error, changed alias, derived-type designator, line shift, loop-carried scalar, private copy of an invariant, bounds below and above the exact layout, wall accumulation, wall scatter without `OMP DO`/`UNIQUE`, gather through a non-table index, pointer set outside the routine (item 8), duplicate inline/sidecar marker, unknown attribute, bad `REDUCTION`, bad `COLLAPSE`, missing `END`, inline equals sidecar, and `HOST` exclusion.
**`port_rename_map.csv` and `port_kernel_map.csv`.** Seeded under `docs/inventory/` by `tools/inventory/port_maps.py`. Columns of the rename map: `prefix_or_component`, `flat_name`, `kernel_or_any` (the three columns of protocol item 2) plus `status` (`generated` = used by a generated kernel, `mapped` = rule fixed, `proposed`) and `note` (type and line of the source). 129 rows: the prefixes `M%`, `SF%`, `SM%`, `MESHES(NM)%`; the wall components `WC%`, `BC%`, `B1%`, `EWC%` with the table names above; `SPECIES_MIXTURE(N)%MW`, `CELL(...)%SOLID`; and every mesh field and work-array alias used by the mass, divergence and velocity kernels (for example `M%U` to `U`, `M%SWORK1` to `RHO_D_DZDX`, `M%ZZ` or `M%ZZS` to `ZZP`). The rename script of protocol item 2 should read this file; the generator's own table (`s5gen_args.json`) must agree with it, and a CI check should compare the two. The kernel map has 126 rows (one per routine with a non-geometry loop, nest ranges at `36975d7`, class counts, time share, churn, `generated_kernels`); `kernel_file` and `shim` are empty until a routine is ported. Routines that are fully geometry are omitted.
**Review of the body-only/surface-changing heuristic** (protocol item 3 and `gpu_callgraph_survey.md` section 8: a hunk is surface-changing only if it adds or deletes a `DO`, `!$OMP`, `CALL`, `USE`, `ALLOCATE`, pointer assignment, typed declaration, or a routine name). It already admits to missing new arrays, private scalars and bounds. Concretely it misses: (a) a new array or scalar read in a plain assignment, for example `A(I,J,K) = B(I,J,K)*C(I,J,K)` where `C` is new (a new kernel argument and a new shim extraction, protocol item 4); (b) a new private scalar `TMP2 = ...` (the `private` clause changes); (c) a loop bound or a stencil offset changed in an expression (`DO I=1,IBAR` to `DO I=0,IBAR` is a `DO` line, but `N1 = IBAR` followed by `DO I=1,N1` is not); (d) a changed index offset (`A(I-1)` to `A(I-2)` widens the stencil and the dummy bounds); (e) a read of a component that is missing from the rename table (`WC%X` with a new `X`); (f) reordered statements that change which value is read; (g) an `IF` guard that now skips a write, changing the read/write sets of the loop. **Recommended improvement:** make the generator the classifier. The merge check regenerates every ported kernel from the merged tree and compares, per kernel, (1) the argument manifest (names, roles, dims, intents), (2) the read/write signature and stencil reach, (3) the private set and (4) `body_sha`. Same manifest and signature with a changed `body_sha` is body-only (regenerate, run the bitwise gate); anything else is surface-changing (stop, list the delta, update shim and tables). This replaces text heuristics by facts the generator already computes, covers hand-ported routines through the same IR if they carry a marker, and costs one generator run per merge. Keep the lexical heuristic only for routines with no marker. **Implemented** as `s5_gen/port_merge_check.py` (usage and class definitions in the s5_gen README; replay of 62 upstream commits in `docs/inventory/port_merge_check_replay.md`): the seven cases (a-g) above are fixtures and all classify as surface-changing with the reason naming the changed manifest field; the manifest adds subscript patterns, access order, conditional-write set, scalar definitions outside the marked range and storage to the golden signature, so it also catches an array whose allocation bounds change although no marked line was edited.

## Risks
- Coverage is limited by layout and by the shape of the code: 163 of 231 translation-eligible loops are not yet accepted by the front end, 57 of them because the survey loop is not a perfect K,J,I nest (the marker route per inner nest covers part of that).
- The `UNIQUE` assertion (distinct walls write distinct cells) is a geometric argument tested only on synthetic walls; thin walls, corner cells and coarse-fine interface cells need a check on a real mesh.
- Table synchronisation is a driver duty; a stale `W_BOUNDARY_TYPE` after an obstruction event gives a wrong result with no diagnostic. A step-level assertion that compares a checksum of the tables against the host records is advisable.
- `UVW_SAVE`/`U_GHOST` are produced by `ccib.f90` (deferred) and `MATCH_VELOCITY` (geometry); the translated wall loops depend on them.
- Aliasing cannot be proved when a pointer is set outside the routine or two work arrays share storage (turb.f90:603 and 626). `RHOP`, `UU`, `ZZP` are re-aimed per step (divg.f90:60-76); the driver must pass the right array.
- Callees are mostly not PURE (223 of 224); emitted with `declare target`.
- nvfortran behaviour of the generated kernels, in particular the wall loops, is untested.
- The test cannot see a dropped `private` clause at `-O2` on a host.
- Fortran syntax upstream that fparser2 cannot read stops the build.

## Open questions
1. Are inline markers acceptable to upstream, or must the sidecar remain a fork-only file?
2. Per-box wall lists: decided (ruling W1): one table set per mesh plus per-box index lists `WLIST_EXT` and `WLIST_INT`; implemented as the `wlist = true` kernel attribute (see "Interaction with the AMReX box layout").
3. Should `NS` stay one argument for `N_TRACKED_SPECIES` and `N_TOTAL_SCALARS`, or become two?
4. Who owns the `UVW_SAVE`/`U_GHOST` producers while `ccib.f90` is deferred?
5. Should the merge check adopt the generator-based classifier above?
6. Does the generated `teams loop` choice hold up under nvfortran? The side-by-side run in `run_gen_on_gpu.md` answers it.

## Wall table work after the wall lists (plan)

1. Direct `EXTERNAL_WALL(IW)%NOM` designator for the NO_FLUX wall loop (velo.f90 L1366): `wall_ref` accepts it without an `EWC` alias, `wall_region` covers the loop's alias list; new table family `EW_NOM`, `EW_NCELL`, `EW_OFF` (extent `NWE`, indexed by the global `IW`; count and offset give the per-wall neighbour list in the mesh data's flat arrays). The loop translation itself belongs to the mesh data side.
2. `NEAR_SURFACE_GAS_VARIABLES` (WALL_BC) with per-surface tables reached through `W_SURF_INDEX`.
3. Mass flux wall tables: `B1_ZZ_F(NWE+NWI,NS)`, `WALL_INDEX` (raw upstream integer), `EXTERIOR` (same shape and flatten rule as `SOLID`), and a Python face-write check (`wall_checks.py`) callable from tests and from the driver at table build time.

## Direct EXTERNAL_WALL(IW)%COMP designator (implemented)

`wall_ref` accepts `EXTERNAL_WALL(IW)%NOM` (and any other scalar component) without an `EWC` alias: it becomes the flat table `EW_NOM(IW)` of extent `NWE`, role `wall`, type `EXTERNAL_WALL`. The subscript must be the loop variable `IW`. In a loop over the internal walls too (`NWE+NWI`), the read must sit under `IF (IW<=N_EXTERNAL_WALL_CELLS)` (or the else branch of `IW>N_EXTERNAL_WALL_CELLS`), else the generator refuses it (the table has no internal entries). The aliases `WC`, `BC`, `B1` of the NO_FLUX wall loop (velo.f90:1463-1559) are recognised as before. `EW_NCELL` and `EW_OFF` are not implemented (their meaning is open). Tests: `test/test_wall_nom.py`.

### Per-surface tables (SURFACE) and the NEAR_SURFACE_GAS_VARIABLES branch
`SURFACE(WC%SURF_INDEX)%COMP` (alias `SF`) becomes `SF_COMP(W_SURF_INDEX(IW))`, with the extent `0:N_SURF+N_SURF_RESERVED`: one value per surface, not per wall, so the driver fills each table once per surface table change and no per-wall copy exists. `W_SURF_INDEX(NWE+NWI)` is a read-only wall table. Rank-1 components that are not species arrays take their axis from `[policy.wall] dims` (`SF_VEL_T(.,2)`); `SF%RAMP(slot)%INDEX|TAU` becomes `SF_RAMP_INDEX|SF_RAMP_TAU(., -N_SURF_RAMPS:NS)` with the slot a PARAMETER (`TIME_VELO`, `TIME_TGF`) or a literal. The tables are read-only: a store to one in a wall loop is refused, because all walls of a surface share the element.
The WALL_INDEX branch (`wall.f90:416-451`) writes only `B1_U_TANG`, `B1_TMP_G`, `B1_RHO_G`, `B1_Q_RAD_IN`, `B1_ZZ_G` at `IW`, so the stores are unique per wall. It is not a callee candidate (derived-type pointer dummies, OPTIONAL arguments, function callee `EVALUATE_RAMP`); the kernel is the loop head plus the inlined branch. Open items: the `SPACING` intrinsic and a function callee for the ramp lookup (flat ramp tables; device/control/external ramps stay on the host). `test_wall_surf.py` checks the tables with stand-ins for those two.

### Order-dependent wall stores: `last_writer` and `gather` (implemented)
Two walls can reach one array element (a solid cell with several gas neighbours, the two walls of a thin obstruction, the walls of one gas cell). Whether the result depends on the order of the walls decides the form; the generator offers one per case and never asserts what it cannot check.
- **`last_writer = "<FLAGS>"`** (L1402 `wall_uvw_nograd`, L1359 `wall_visc_mirror`): the serial loop is last-writer-wins (owner rule SP2: the highest wall index that passes the guards; no distinct-target assertion). `<FLAGS>` is a new read-only integer wall table (`WALL_FLAG`, extent of the loop) that the driver builds with `wall_checks.last_writer_flags(t, target, n_exec)`; it is 0 exactly for a storing wall that a later storing wall overwrites. The loop body starts with `IF (<FLAGS>(IW) == 0) CYCLE`, so the flagged walls store to distinct elements and the kernel is independent of the iteration order. `target(t, iw)` is the element the wall stores to, or None when the wall does not pass the guards of the loop (`uvw_nograd_target`, `visc_mirror_target`). L1359 also needs `visc_mirror_hazards` empty (no stored cell is read as a gas cell by another wall; the serial loop would feed the stored value on).
- **`gather = "<ARRAY>"`** (L0375 `wall_corr_kdtd`, L0394 `wall_bc_dp`; owner rules SP3, P3): an accumulation `DP(g) = DP(g) - expr` (or a copy that overwrites) reaches one element from several walls; the sum is not associative, so the order of the walls matters. The loop becomes two regions of one kernel: region 1 is the wall loop without the stores into `<ARRAY>` (the other stores keep their own contract: UNIQUE, IDEMPOTENT, `last_writer`); region 2 runs over the cells and, per cell, over its walls in ascending wall index through the CSR tables `W_CSR_<key>_PTR`, `W_CSR_<key>_LIST` (`wall_checks.csr_cell_walls`; key `GAS` = gas cell IIG,JJG,KKG, key `WC` = wall cell II,JJ,KK, taken from the subscripts of the stores), executing the body with every other store dropped, so each element is updated by one thread in the serial order starting from the value already in the cell. If region 1 would hold no store, only region 2 is emitted.
  Source conditions, all checked on the text: every store into `<ARRAY>` is indexed by the gas-cell triple or the wall-cell triple (one key per kernel, not in a one-line IF); every read of `<ARRAY>` is the element the statement updates or, as the whole right-hand side of a copy, the other triple (`DP(II,JJ,KK) = DP(IIG,JJG,KKG)`); no read of `<ARRAY>` anywhere else; no CALL; region 2 reads nothing that region 1 stores. The copy case needs the table-build check `wall_checks.gather_foreign_hazards` (no stored cell is also copied from; a MIRROR wall of a thin obstruction breaks it and the driver must refuse the mesh).
- **`B1 => BOUNDARY_PROP1(WC%BC_INDEX)`** (divg.f90:1581) is accepted as a B1 alias; the flat B1_* tables are indexed by the wall, so the driver runs `wall_checks.check_b1_bc_index` (BC_INDEX equals B1_INDEX at every wall; patch 0004 would make the source say B1_INDEX).
- Rank-1 mesh arrays read at `BC%II|JJ|KK|IIG|JJG|KKG` with an offset of at most 1 (`R(BC%II-1)`) are read-only gathers (layout exact); the bound is the ALLOCATE extent, the offset stays inside it for every wall of a consistent mesh.
