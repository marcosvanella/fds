# B5: UGLMAT reference vs the P2 pressure prototype on `ns2d_16_int_1to2_refinement`, and the one-cell-thick setup

Data, inputs, scripts and logs: `vv-runs/B5/` (README there). FDS side: `vv-runs/A-38/` (t ≈ 1) and `vv-runs/B5/fds_step1/`
(one step). Prototype: the P2 composite-MLMG setup (`prototypes/p2_pressure_mlmg/src/p2_main.cpp`, `run_mms`), copied to
`vv-runs/B5/src/b5_ns2d.cpp` with the ns2d geometry and RHS. AMReX 99ddfda, HYPRE v2.32.0-24-g63331f19c, FireX 36975d765f
GNU release build. Runs used 1 rank (3 for the rank check), OMP_NUM_THREADS=1.

## 1. What REC-I2 criterion 2 compares

Source: `pressure/01-amr-mapping-spec.md` §I.3, REC-I2 item 2:
"‖H_AMR − H_exact‖ ≤ 1.1 × ‖H_UGLMAT − H_exact‖, both mean-removed, and observed order ≥ 1.8 under 2× refinement (FR-014)".
* **Single solve or evolved field.** The criterion does not say. It sits in §I.3, directly after §I.2, which defines the pressure
  comparisons as a **single frozen-state solve with the same RHS, ideally taken from the FDS run's first step**, not a time-marched
  run (§I.2, "The comparison is on a single frozen-state solve"). §I.3 is about the C/F discretisation difference of the two
  Poisson operators. The criterion is therefore read as a frozen-state single solve with a shared RHS from FDS step 1.
  P2 is a pressure-only prototype, so this is also the only reading it can test.
* **Time.** First step. B5 uses dt = 1e-6 (`LOCK_TIME_STEP`), so that the step-1 H is the Poisson solution for the exact initial
  velocity and the time lag between the solve and H_exact(t) is negligible. H_exact is evaluated at t = 1e-6.
* **Norm and region.** Not stated in REC-I2. §I.2 uses a volume-weighted L2 over uncovered valid cells with the volume-weighted
  mean removed. That is identical to the A-38 H norm (area-weighted L2 over the 12 coarse and 1 fine FDS meshes = uncovered coarse plus fine
  cells, domain mean of H and of H_exact removed). Region: the whole domain is the gate. Fine and coarse regions are reported.
* **Not the same as D-040.** The FR-014 gate (D-040) is a different check: the time-evolved AMR code at t ≈ 1, for u, w and H,
  against A-38. It needs the Phase-4 AMR time stepper and cannot be evaluated with P2.

## 2. Comparison made

The prototype reproduces the int_1to2 geometry:
* periodic 2π × 2π, level 0 N × N;
* level 1 at ratio 2 over the coarse cells [N/4, 3N/4) in x and z, which is exactly the FDS fine mesh XB = π/2…3π/2;
* the level-1 grids are generated by `AmrMesh` from tags, and the patch covers the region exactly at every N.

Solver settings: maxorder 2 (and 3), tol_rel 1e-12, REC-C2 composite RHS mean removal, periodic MLMG. Every solve reaches a true
composite ‖r‖₂/‖b‖₂ ≤ 5.3e-13.

| pair | AMR side | UGLMAT side | like-for-like? |
|---|---|---|---|
| **A (gating)** | prototype solve with b_FDS | FDS UGLMAT-HYPRE step-1 H (dt = 1e-6) | **Yes**: same RHS, same frozen state, same norm. Only the C/F operator differs. b_FDS = L_UGLMAT·H_FDS is rebuilt with the UGLMAT stencil from FireX `pres.f90` GET_H_MATRIX (AF = min(AF_int, AF_ext), B = AF/(D_INT+D_EXT), half-width distances) |
| B | prototype, exact analytic RHS | same stencil re-implemented (dense direct solve), exact RHS | Yes for the operator, but the UGLMAT side is a re-implementation, not FDS |
| C | prototype, exact RHS | FDS step-1 H | **No**: different RHS. Informational |
| – | – | A-38 at t ≈ 1 (H 0.1107 / 0.0456 / 0.0211) | **No**: time-evolved. Not comparable with a single solve |

Checks on b_FDS:
* The composite integral is zero to 6e-17 relative.
* The recomputed FDS step-1 norm equals the A-38 script's value.
* The interior of b_FDS converges to the exact Laplacian at second order.
* In the fine-side C/F layer, the FDS RHS error does not converge (RMS 1.2 / 1.6 / 2.4; coarse side 1.0 / 0.69 / 0.60). This is FDS's
  own interface RHS error. It is shared by both sides of pair A, and it is why FDS's step-1 H converges below second order.

## 4. Verdicts

* **REC-I2 criterion 2: PASS at maxorder 2** on the like-for-like pair A:
  * L2 ≤ 1.1 × UGLMAT at every N (ratios 0.92 / 0.83 / 0.68);
  * observed order 2.01 / 2.03 ≥ 1.8.
  The operator-only pair B also passes (1.02 / 1.01 / 0.93; order 2.03 / 2.01).
* **maxorder 3 (REC-I3 asks for both):** pair A is 1.108 at N = 16, a marginal fail by 0.008. N = 32 and 64 pass. Order 1.99 / 2.02.
  Maxorder 2 is the accepted multi-level setting (P2 §2.1), so this does not block. Record maxorder 3 as not meeting 1.1× at N = 16 on this case.
* **D-040 (FR-014 gate): not evaluable with P2, still open.** The gate is on the time-evolved AMR run at t ≈ 1 for u, w and H. For information only:
  applying the D-040 form to the single-solve H of pair A would pass (order 2.01 / 2.03 ≥ FDS − 0.1 = 1.77 / 1.65; ratio ≤ 1.1 at each N).
  This says the AMReX pressure operator is not the component that would make the AMR code fall behind FDS. It does not replace the Phase-4 check.
* **Decomposition:** 3 ranks vs 1 rank at N = 64 differ by ≤ 4.8e-14 (thin) and ≤ 2.7e-15 (2-D).

## 5. One-cell-thick direction (FDS IJK(2) = 1)

The provisional setup **works, and gives the true-2-D answer to solver round-off**, but the MLMG convergence rate degrades with N.

**Exact parameters used** (3-D AMReX, `inputs/proto/thin_*.inputs`):
```
geometry.prob_lo = 0.0 -0.05 0.0      geometry.prob_hi = 2π 0.05 2π      geometry.is_periodic = 1 1 1
amr.n_cell = N 1 N                    amr.max_level = 1                  amr.ref_ratio_vect = 2 1 2
amr.blocking_factor_x = 8             amr.blocking_factor_y = 1          amr.blocking_factor_z = 8
amr.max_grid_size = 32                amr.n_error_buf = 0                amr.grid_eff = 1.0      amr.n_proper = 1
LPInfo().setHiddenDirection(1); MLPoisson(geom, grids, dmap, info); setMaxOrder(2 or 3); periodic domain BC in x, y, z
MLMG: tol_rel 1e-12, tol_abs 0, maxiter 2000 (the P2 default of 200 is not enough at N ≥ 32)
```

Results:
* **It runs.** AmrMesh builds the level-1 grids with ratio (2,1,2) and blocking factor 1 in y. The fine domain is 2N × 1 × 2N, and the patch is covered exactly.
* **Same as 2-D.** Compared with an AMREX_SPACEDIM = 2 build of the same AMReX commit and driver (ratio 2 2, blocking factor 8), H agrees to
  ≤ 2.5e-12 absolute (≤ 7e-13 relative to max|H|) for every N, maxorder and RHS. The norms are identical to all printed digits. The difference is at the
  1e-12 solver-tolerance level: these are two converged iterative solves, not bitwise results. A 3-D y-invariant run (2 coarse y cells,
  ratio 2 2 2, no hidden direction) also agrees with 2-D to ≤ 7e-13.
* **Negative control.** Ratio (2,1,2) without `setHiddenDirection` aborts at setup with `MLLinOp: Uncoarsenable domain`. The hidden
  direction is required.
* **Convergence is not scalable.** MLMG iterations to 1e-12, hidden direction vs 2-D:
  * N = 16: 122 vs 9;
  * N = 32: 311 vs 9;
  * N = 64: 546 vs 9.
  The same holds at maxorder 3. With 1 rank the time is still small (0.43 s at N = 64), but the count grows roughly like N.
  At the P2 default `maxiter = 200`, N = 32 and 64 abort with "MLMG failed" (resid/bnorm 3.5e-8 and 7.4e-4).
  * Verbose traces show the problem on the fine AMR level. After the coarse-level correction, its residual is about 4× larger than in the
    2-D solve, and the smoother does not remove it. That points at the AMR-level correction or C/F path under `hidden_direction`.
  * Other knobs:
    * 8 pre/post smooths: 99 iterations (N = 32), 128 (N = 64);
    * Jacobi instead of GSRB: no better;
    * HYPRE bottom solver: no effect.
  * The root cause in AMReX was not found in B5.

**Verdict:** confirmed for correctness: `ref_ratio_vect 2 1 2`, `blocking_factor_y 1` and `setHiddenDirection(1)` reproduce the true 2-D
composite solve to round-off. **Not confirmed for production as-is**: two-level MLMG convergence with the hidden direction degrades
roughly linearly with N. The y-invariant alternative (2 coarse cells in y, ratio 2 in y, no hidden direction) converges in 8
iterations with the same answer. However, it doubles the cells in y and departs from FDS IJK(2) = 1.

## 6. Open items

1. **Hidden-direction convergence** (section 5): find the cause in AMReX 99ddfda (fine-AMR-level correction under
   `hidden_direction`) or pick a mitigation for the production driver. Options: more smoothing; the y-invariant layout; or report
   upstream. The FR-010 wording should keep the hidden-direction setup provisional until this is settled.
2. **D-040** still needs the time-evolved AMR run at t ≈ 1 (u, w, H) against A-38 (Phase 4). Nothing in B5 addresses it.
3. **maxorder 3** misses 1.1× at N = 16 by 0.008 on pair A. This is informational while maxorder 2 is the multi-level setting.
4. The b_FDS reconstruction depends on the re-implemented UGLMAT C/F coefficient. It was checked against `pres.f90` and by conservation.
   A direct dump of the FDS RHS was not done: it would need an FDS source change, which B5 rules out.
5. The FDS step-1 RHS has a non-convergent one-cell error layer at the 2:1 interface. It is the likely start of A-38's sub-second-order
   behaviour. That belongs to the FDS baseline; the AMR code does not share it.
