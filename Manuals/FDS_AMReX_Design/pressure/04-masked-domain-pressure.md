### 1.2 How FDS treats the gap
* **Every mesh gets wall cells on all six external faces** (init.f90:76-107, `INIT_WALL_CELL(... DEFAULT_SURF_INDEX ...)`). A face with no
  neighbour mesh becomes a solid exterior wall. So in FDS the gap is an **exterior wall of each mesh**. It is not solid cells.
* **Per-mesh FFT face types:**
  * A face is Neumann by default (init.f90:2493-2495).
  * It becomes Dirichlet if it carries an OPEN vent (init.f90:2497-2526) or **any** interpolated wall cell (init.f90:2528-2554).
  * Each wall cell inherits the face type (init.f90:2605-2625).
* **On a Neumann face** the gap wall has exact no-flux, `BXS = HX(0)·(−FVX + DUNDT)` (pres.f90:77-93).
* **On a Dirichlet face** (e.g. a mesh face that touches another mesh on one part and the gap on another), the gap part gets
  `H_b = ½(H_ghost + H_gas) + WALL_WORK1` (pres.f90:97-110).
  * `WALL_WORK1` is updated from the normal-velocity error (pres.f90:1056) until `VELOCITY_ERROR_MAX < VELOCITY_TOLERANCE`
    (default 0.5·Δ, read.f90:10159-10161) or `MAX_PRESSURE_ITERATIONS` (default 10, cons.f90:559).
  * So FDS's no-flux on gap walls is exact on pure-gap faces and ≤ `VELOCITY_TOLERANCE` on mixed faces.
* **Interfaces between meshes** are Dirichlet with the same iteration (01 §D reason (1)).
* **The FDS reference for all 40 cases is therefore per-mesh FFT plus pressure iterations**, not UGLMAT (`solver` empty in the CSV;
  default FFT, `DEFINE_PRES_METHOD`, func.f90:7143 per requirements.md:192). Its result carries interface and mixed-face velocity
  errors up to `VELOCITY_TOLERANCE`.
* **Zones.** The pressure-zone flood fill stops at solid cells. Disjoint mesh groups become separate zones (19 of the 40 have
  several), each with its own `D_PBAR_DT` and its own singular per-mesh solves.

### 1.3 Vents on gap-facing mesh faces (A-46 flag)
The CSV does not list them, so two T2 inputs were read **[derived from input coordinates, snapping not run]**:
* `Restart/device_restart_a.fds:29` `&VENT SURF_ID='OPEN', XB=3.1,3.1,12.7,20.4,0.0,2.6`:
  * snaps to x = 3.2, the hi-x face of mesh 4 (line 9, x ∈ [−6.4, 3.2], dx 0.4);
  * for y > 7.2 that face borders the gap (mesh 2 ends at y = 7.2, line 7; mesh 3 starts at x = 7.2, line 8);
  * **an OPEN (Dirichlet) boundary on a face inside the bounding box, next to gap cells.** The same applies to `device_restart_b`
    and `device_restart_base_case` (same meshes per CSV).
* `Pressure_Solver/hallways.fds:15` `&VENT XB=3.0,3.0,3.0,4.0,3.0,4.0, SURF_ID='OPEN'`:
  * the whole lo-x face of mesh 5 (line 9), bordering the gap (mesh 1 covers only y, z ∈ [0,1], line 5);
  * same situation.

**So the masked-domain solver must support Dirichlet (OPEN) faces between gas and gap cells.** This rules out any route that can only
make gap faces Neumann. V&V's A-46 rerun should list all such vents **[VERIFY count]**.

### 1.4 What AMReX offers (read at 99ddfda)
* **`FFT::Poisson`**: whole rectangular domain, one homogeneous BC type per face (FR-037 validity; 02 §7). There is no mask.
* **MLMG with an overset mask** (cell-centred `MLABecLaplacian`/`MLPoisson`, mask 1 = unknown, 0 = known; AMReX_MLABecLaplacian.H:45,
  80; AMReX_MLPoisson.H:63, 94). Known cells are skipped by the smoother (AMReX_MLABecLap_3D_K.H:46, 289, 398), and β is rescaled at
  known/unknown faces on coarse MG levels (:750-786; AMReX_MLABecLaplacian.H:742-790).
  * **With an overset mask, MLMG never flags the problem singular:** "For now this assumes that overset regions are treated as
    Dirichlet bc's" (AMReX_MLABecLaplacian.H:830-831).
  * So a gas component that touches known cells only through β = 0 faces is truly singular while MLMG treats it as non-singular. It
    needs a pin (below).
* **Non-covering level 0 with a Neumann coarse/fine BC.** If the solver's level-0 BoxArray does not cover the domain,
  `m_needs_coarse_data_for_bc` is set (AMReX_MLLinOp.H:1238-1240, 1514). `setCoarseFineBC(nullptr, r, LinOpBCType::Neumann)`
  (AMReX_MLLinOp.H:251-266, 1777-1784) then gives homogeneous Neumann on the uncovered boundary (the bndry data is zero,
  AMReX_MLCellLinOp.H:852-858; type at :878). Singularity is detected (AMReX_MLPoisson.H:233-240; AMReX_MLABecLaplacian.H:846-874).
  The docs describe this for a base level > 0 and allow `nullptr` (LinearSolvers.rst:238-263).
  * The C/F BC type is **one type for the whole uncovered boundary**, so OPEN vents on gap faces cannot be represented.
  * It asserts no overset mask in that branch (AMReX_MLPoisson.H:236).
  * The HYPRE bottom solver honours the type (AMReX_MLMG.H:2419-2425).
* MLMG β coarsening averages face β arithmetically (03 Q5), so β = 0 gap faces "leak" only on coarse MG levels (convergence, not answer).

## 2. Options

Cost basis:
* **[estimate]** 02 §2.3/§7: FDS per-mesh FFT 14–15 ns/cell per solve × k iterations; `FFT::Poisson` 30–45 ns/cell (one node);
  MLMG 90–250 ns/cell.
* **[measured]** P2, 64³, 4 ranks, indicative: MLMG ≈ 7× (6–9×) `FFT::Poisson` per solve (D-032).
* The level-0 bounding box has N_bb = N_gas / fill cells.

### (a) Single-level MLMG on the masked domain — **recommended, realisation (a2)**
**(a2) Bounding-box level 0, gap cells masked (the "gap mask").**
1. **Operator.** `MLABecLaplacian` (β ≡ 1 in gas, i.e. the same constant-coefficient H operator as the FFT; `a = 0`), with
   `setMaxOrder(2)` (D-032 (1)). Overset mask = 0 on every gap cell. β_face = 0 on every gas–gap face. The gap cells are thereby out of
   the system, and the wall no-flux is **exact**. The wall's prescribed normal velocity is already in `Ũ` (01 §F, first row).
2. **OPEN vent on a gas–gap face.** Set the gap cell behind it to a known value `H_b` (the FDS OPEN value,
   `PRESSURE_SOLVER_COMPUTE_RHS`, 01 §F), and set **β_face = 2** on that face. The face flux is then 2(H_b − H_gas)/dx², which is exactly
   the linear face-Dirichlet flux (ghost 2H_b − H_gas) of `setMaxOrder(2)`, `FFT::Poisson`'s odd BC and Crayfishpak **[derived]**.
   Multi-level variants are out of scope here.
3. **Null spaces.**
   * Flood-fill the gas cells over faces with β ≠ 0 at setup (static: the mask depends only on `&MESH` geometry). This gives the
     connected components.
   * Components with an OPEN (known-value) face are non-singular.
   * In every other component, pin one gas cell (mask 0, value 0). The component is truly singular, and MLMG will not treat it as
     such (AMReX_MLABecLaplacian.H:830-831).
   * Choose the pin deterministically (e.g. the lowest global cell index in the component), so it is layout-independent.
4. **Compatibility and gauge.**
   * Before every solve, apply D-032 (2)'s mean removal per pressure zone over gas cells only, with the exact sum.
   * The pinned cell's dropped equation is then satisfied automatically. Its residual equals the removed incompatibility (round-off).
   * If a zone could contain more than one component (possible only for multi-seed `&ZONE`, **[VERIFY]**), remove the mean per component.
   * After the solve, apply the per-zone GLMAT gauge (01 REC-C3), which removes the pin's arbitrary constant.
   * The FR-039 true-residual check runs as specified, including the pinned cells' equations.
5. **Obstructions inside the meshes:** unchanged E-1 (IBM forcing plus obstruction iteration, `VELOCITY_TOLERANCE`), exactly as in the
   FFT path. Only the inner solver differs. This also keeps run-time OBST creation/removal free of any MLMG re-setup
   (`device_restart_a` has a timed OBST, lines 15-16).
6. **Iteration count.**
   * The interface iteration disappears (single level, as with the FFT; 01 §D (1)).
   * The gap/mixed-face iteration disappears (exact Neumann).
   * Only the OBST and baroclinic iterations remain. So k_(a) ≤ k_FDS.

**Cost.** Per step relative to FDS: r ≈ (90–250)/(14–15) / fill × k_(a)/k_FDS ≈ **(6–18)/fill × k_(a)/k_FDS** **[estimate]**.
* Restart anchors (fill 0.419): 14–43 × k_(a)/k_FDS. Absolute: 24.8 k bounding-box cells → ≈ 2–6 ms per solve, single core
  **[estimate]**. Negligible for V&V.
* **`stairwell` is the outlier:** 18.0 M bounding-box cells → ≈ 1.6–4.5 core-s per solve **[estimate]**, against ≈ 25 core-ms × k for FDS.
  Run time, not correctness, is at risk (see §4 open point O2).
* Memory: the gap cells cost ~64 B/cell in the solver (02 §3). The Integration Lead's bounding-box level 0 already allocates every field
  there.

**(a1) Solver-only non-covering BoxArray (gas boxes only) with a Neumann C/F BC.**
* Advantages: exact Neumann, cost ∝ gas cells (stairwell 11× cheaper than (a2)), and AMReX detects the singularity itself.
* **Not selected as the baseline**:
  * it cannot represent OPEN vents on gap faces (one C/F BC type), and at least `hallways` and the three restart anchors need them (§1.3);
  * the level-0 use is outside the documented case (base level > 0);
  * it needs RHS/solution copies between the level-0 BoxArray and the solver BoxArray.
* It is a candidate optimisation for low-fill cases without gap-face vents (O2).

### (b) `FFT::Poisson` on the bounding box plus a correction
* **(b1) FDS-style obstruction iteration.** Gap cells are treated like OBST cells: D = 0 there (divg.f90:1547-1555), wall-face forcing
  (`NO_FLUX`, velo.f90:1348-1563) and the `VELOCITY_TOLERANCE` iteration.
  * Cost: (30–45) ns × N_bb × k_b, where k_b now also carries the gap walls, which are the largest solid surfaces in these domains
    (fill down to 0.09).
  * No-flux holds only to `VELOCITY_TOLERANCE`, including on the faces that FDS itself treats *exactly* (pure-gap Neumann faces, §1.2).
    So it is further from the FDS reference than (a) on those faces.
  * The operator connects disjoint zones through gap cells, so per-zone solvability rests on the iteration alone.
  * OPEN vents on gap faces cannot be expressed. FFT BCs exist only on domain faces, and an interior Dirichlet face would need a new
    forcing that FDS does not have.
* **(b2) Capacitance-matrix / immersed correction.**
  * Exact in principle, but new code that neither FDS nor AMReX has.
  * m = number of gas–gap faces is 10³–10⁵ here **[estimate]**, so a dense m×m capacitance matrix is out. A Krylov solve on the
    capacitance system needs one bounding-box FFT per iteration (tens of iterations **[estimate]**), which is at or above MLMG's cost.

### (c) Gap cells as gas with zero velocity forced
* **Zones.** Gas-flagged gap cells would join disjoint meshes in the zone flood fill. This is wrong for the 19 multi-zone cases.
  Keeping the gap solid for zones but gas for the solver is option (b1).
* **Discretisation.** It does not match FDS's multi-mesh discretisation: FDS has no cells in the gap, only exterior walls (§1.2).
* **Agreement with FDS.** The two approaches converge to the same no-flux limit only within `VELOCITY_TOLERANCE`. They cannot agree
  within eps_H or bitwise, and eps_H does not apply anyway (§3).
* **Vents.** The OPEN-vent problem of (b) remains.

     iteration, mixed-face gap walls to `VELOCITY_TOLERANCE`, and no bit-parity reference for multi-mesh (requirements.md:29, D-022).
2. **Same-discretisation solver check (eps_H).**
   * A single solve on frozen input, (a2) against FDS `SOLVER='UGLMAT'` on derived copies (A-41) of `hallways`,
     `device_restart_a` and `simple_duct`. UGLMAT numbers gas cells only across meshes, with exact Neumann on exterior walls
     (pres.f90:5750-5759, 01 §E), i.e. the (a2) discrete problem.
   * Metric: requirements.md §2.1a, eps_H = max(1e-8, 2.4e-12·N²), volume-weighted mean removed per zone, relative L2.
   * **[VERIFY]** that UGLMAT places the OPEN Dirichlet value on the face (linear ghost) as (a2)'s β = 2 rule does. If it uses a
     different location, compare on the gap-face-vent-free cases only.
3. **Box regression.** On box-domain FR-001 cases, (a2) with an empty mask agrees with `FFT::Poisson` within eps_H. This is the FR-039
   acceptance, reused.
4. **Solver health.**
   * Per zone, the removed mean is ≤ 1e-10·‖b‖ (03 Q3 diagnostic).
   * The FR-039 true-residual check passes.
   * Pins and components are bitwise identical at 1/2/4/8 ranks and two `max_grid_size` values (FR-005).

## 4. Recommendation
**Adopt (a2): a single-level MLMG "gap mask"** (overset mask 0 on gap cells, β = 0 on gas–gap faces, β = 2 plus known value behind
OPEN vents on gap faces, one deterministic pin per sealed component, D-032 mean removal and gauge). Obstructions inside the meshes stay
on the FFT-path E-1 treatment.

**Rationale:**
* It is the only evaluated route that is exact on the gap walls (as FDS is on pure-gap faces) and that also handles gap-face OPEN
  vents (restart anchors, `hallways`).
* It keeps disjoint zones disjoint.
* It needs no new numerical method: it is the E-2 machinery of 01 §E restricted to static gap cells, with MLMG already validated in P2.
* It has a clean same-discretisation reference (UGLMAT) for an eps_H check.
* Its cost penalty is irrelevant for 39 of the 40 cases (≤ 0.52 M bounding-box cells each **[derived]**) and bounded for `stairwell`.

**Rejected:**
* **(a1), non-covering solver BoxArray with a Neumann C/F BC:** cannot express OPEN vents on gap faces (single C/F BC type), and its
  level-0 use is outside AMReX's documented case. Kept only as a possible optimisation (O2).
* **(b1), bounding-box FFT with the FDS obstruction iteration:** approximate no-flux even where FDS is exact, extra iterations on the
  largest walls, connected zones, and no way to put OPEN on an interior face.
* **(b2), capacitance/immersed correction:** new, unvalidated code whose Krylov cost is at or above MLMG, for no accuracy gain over (a2).
* **(c), gap as gas with forced zero velocity:** merges disjoint zones, is not FDS's discretisation, and agrees with FDS only to
  `VELOCITY_TOLERANCE`.

**Phase.**
* REC-E1 (01 §E) places E-2 in Phase 4. The gap mask must be pulled forward to **Phase 2**, because FR-006's uniform subset gates
  Phase 2 exit (requirements.md:98, 420).
* The scope is small: single level, static mask, no C/F, no OBST masking.
* The overset mask needs the C++ interface (README Q8). This is an ADR-001 input.

## 5. Fit with D-021, D-032 (5) and FR-039 (proposed wording, for the Chief Architect and Spec Lead)
* **D-021.** No change in substance. Its validity condition ("a single unstretched level with one BC type per domain face") already
  excludes a masked level 0, whose gap walls are internal boundaries. Proposed clarifying sentence for FR-037's Validity: "A level 0
  with masked (gap) cells is outside the `FFT::Poisson` validity domain; such runs use the single-level masked MLMG path (R-47)."
* **D-032 (5).** Proposed: "FFT whenever the hierarchy is a single uniform level **on a box domain (no masked level-0 cells)**.
  Single-level masked domains use single-level MLMG with the gap mask."
* **FR-039 selection** gets a third branch:
  * `FFT::Poisson` for a single level on a box domain;
  * single-level masked MLMG for a single level with gap cells;
  * composite MLMG once a refined level exists (with the same gap mask on level 0).
  * The mask is static, so a masked run never switches between FFT and MLMG. D-032 (1)'s maxorder-2 reason still applies to refined
    variants of box domains.
* **FR-039 acceptance.** "FFT vs MLMG on identical input" is replaced for masked domains by §3 item 2 (UGLMAT, eps_H).
* **R-47.** The mitigation is chosen (this note). The trigger stays: T2 failure on a non-box case.
